# 播放资源边界

原画使用 Service Worker 解密 URL；已生成的原画转封装／转码使用 MSE 分段播放。
两条路径都不能因文件变大而保留整部视频。

## 原画与解密流

`frontend/public/sw.js` 的完整读取和 Range 读取共用一个 pull 驱动的实现：

- 每条响应最多持有一份 4 MiB 密文批次、六个并行块解密结果及两个待消费明文块。
- 消费者停止拉取后，不再读取下一批密文。上游始终发有限 Range，请求失败或返回
  不匹配的范围／长度立即终止；AAD 使用全文件块序号，尾块保持正确长度。
- 原生 video/audio 的 Range 响应最多覆盖 4 MiB 明文，始终返回准确的 206 和
  Content-Range，包含 `bytes=0-` 请求。播放器按需请求下一范围，也可直接跳到文件尾
  读取 MP4/MOV 索引。普通下载不截断响应。
- 取消请求、撤销解密 URL 或清除密钥会关闭相关上游请求、释放队列。
- 视频／音频不进入明文 Cache API。小文档保留原有离线缓存，单文件最多 64 MiB。
- 解密描述中的 `size: null` 表示未知大小（列表缩略图），`size: 0` 表示真正的空文件。
  未知大小时从对象响应的 Content-Length 和五字节加密头推导明文大小，读到头部后
  立即取消探测响应，正文仍复用有界 Range 解密。不依赖 CORS 暴露 Content-Range。

旧 Range 分支在 ReadableStream.start() 里循环到 EOF，没有消费端背压；
`bytes=0-` 因此可能把整个大视频排入队列。仅限制并行 WebCrypto 数量不足以约束
已解密、等待播放器消费的明文。

## MSE 分段播放

`frontend/src/composables/useRenditions.ts` 限制前瞻为 45 秒／估算 32 MiB，后留为
30 秒／估算 16 MiB，先触及的边界生效。估算来自分片尺寸和时长，不是浏览器 RSS
保证；保留完整的边界分片及关键帧会有粒度偏差。单个派生分片超过 64 MiB 时回到
有界原画路径，避免无上限 arrayBuffer()。

缓冲清理会删除连续 TimeRanges 内已播放的前缀；向后拖动也会删除超出前瞻窗口的
尾部，包括同一连续区间。播放到末尾后仍保持清理和重新定位能力。
前缀删除边界向下取整到完整独立分片边界，配额不足时的紧缩清理也遵守此约束。
MSE 的 remove() 会连带删除直到下一关键帧的依赖帧，不能把字节预算边界直接作为
删除终点，否则可能删除当前播放位置仍需的数据。
切画质／关闭时取消分片 fetch，暂停媒体元素、移除 src 并 load() 释放浏览器解码器。
已存在派生视频时先选择它，不先启动一次多余的原画请求。

## 验证

```bash
cd frontend
node --test --test-timeout=10000 tests/decrypt-stream.test.mjs
E2E_REUSE_SERVERS=1 npm run test:e2e -- e2e/playback-resources.spec.ts
npm run check
npm run build
```

Node 测试直接执行生产 Service Worker，检查 8 GiB 逻辑数据的慢消费、完整／Range
读取、尾部寻址认证、取消、缓存离线读、错误范围和认证失败。

浏览器测试以 ffmpeg 生成低分辨率视频，将 MP4 索引移到 8 GiB 稀疏文件末尾，测试
原生 video 的打开、播放、暂停、前后寻址及关闭。密文由独立本机接收端按 Range
现场生成，实际走浏览器 Service Worker 和播放器，不需要账户或上传测试数据。
该用例验证超大文件和尾部索引，不模拟 8 GiB 高码率视频的解码复杂度。

另一个真实 MSE 用例验证连续播放的缓冲前缀回收、向后寻址的尾部回收和关闭清理。
补充分片预算用例以 MP4 free box 将真实分片尺寸填充至 32 MiB，保留两秒 GOP，验证
按字节清理及注入 QuotaExceededError 后均能保留当前分片并继续播放。它验证实际
浏览器的关键帧依赖行为，不模拟高码率解码负载。含缩略图在内的 4 项 Chromium 回归通过。
Linux 上通过 CDP 和 /proc 采样浏览器进程 PSS；它包含浏览器基础开销，与 JS 缓冲额度
和 RSS 均不同。

2026-09-26（HKT）本机验证：6 项 Node 测试、2 项 Chromium 播放测试，以及类型检查、
生产构建通过。8 GiB 稀疏测试片在打开、播放和四次前后寻址后共读取密文
62,810,312 字节（约 60 MiB）；单次上游 Range 最大 4,130,532 字节。
浏览器进程 PSS 采样基线 309,163,008 字节，采样峰值 563,231,744 字节（约 537 MiB）。
暂停后的观察窗口内读取停止，关闭后没有继续请求。真实高码率源的解码开销和用户端
复测仍待确认。

缩略图兼容性补充验证：9 项 Node 测试及 3 项 Chromium 测试通过。新增用例覆盖
未知大小的单块／整块／尾块、空文件和无效长度，以及真实文件列表在播放前、返回后、
整页刷新后的 WebP 解密显示与字节比对。用户已反馈大视频播放内存明显改善。

### 关闭后的自然回收观察

```bash
DOMUS_E2E_PLAYBACK_MEMORY=1 E2E_REUSE_SERVERS=1 npm run test:e2e -- \
  e2e/playback-resources.spec.ts -g 'without inspector'
```

这个可选用例使用独立 Chromium，只通过 CDP Runtime/Page 操作生产解密与播放器代码。
不启用 Network 记录、不强制 GC、不在三轮之间刷新页面。常规 Playwright 的网络记录
会保留响应数据，关闭 trace/video 仍不足以消除对内存测量的影响。

本机 8 GiB 稀疏测试片的三轮播放／四次寻址／关闭采样结果（全部 Chromium 进程 PSS）：

| 轮次 | 关闭前 | 关闭后 30 秒 |
| --- | ---: | ---: |
| 1 | 594,503,680 B（约 567 MiB） | 514,811,904 B（约 491 MiB） |
| 2 | 597,059,584 B（约 569 MiB） | 549,652,480 B（约 524 MiB） |
| 3 | 588,777,472 B（约 562 MiB） | 548,217,856 B（约 523 MiB） |

最初基线为 503,578,624 B。关闭后 1～5 秒变化较小，30 秒采样均出现回落，第二、
三轮的关闭后占用基本持平。该测试验证有限三轮内的回收表现，不承诺任意浏览器或
真实高码率视频都在 30 秒内回到原始基线；停止请求和释放引用是立即执行的动作，
进程物理内存回落仍由浏览器调度。
